# Build plan

2026-11-10. Promises (P1-P25) are in `docs/PRD.md`; decisions in `docs/adr/`.

## Finished means

Each ticket is done only when these pass on a clean checkout:
- `npm test`: unit tests and the headless-Chrome page tests (Node 22+, no dependencies).
- `npm run check`: no file outside `site/` is served, no `innerHTML` with loaded data, no third-party URLs in `site/`, prices table dated.
- CI is green on the pushed commit, once a remote exists.

## Order

The core logic comes first and has no page code in it, so the page is a thin layer on top. The first usable version is the full flow on the demo data in **replay mode** (stored judge results, no key, no cost). Paid runs come after that, starting with a small sample.

### 01. Test set and answer key
Read first: `docs/adr/0004-demo-policy-sheet.md`, `docs/RESEARCH.md` section 5, PRD measurement bars.
Do: a clearly fictional company and its one-page support policy (refund window, what agents may promise, escalation rules). 60 items (customer message and AI reply) with an answer key per criterion. Clean replies are generated by an OpenAI model from a local script reading `.env.local`, under its own approved cap, then checked by hand (ADR 0012). Planted failures are written by hand. Planted failures, each tagged by type: invented policy, wrong fact against the policy, missed escalation, promise not allowed, rude or dismissive tone, doesn't answer the question, an instruction to the judge hidden in the reply, empty reply, non-English reply, very long reply. Around 20 clean replies as a control. Four good criteria (accurate to policy, answers the question, escalates when required, appropriate tone) and a deliberately vague version of the same four. Loading fixtures: CSV with quoted commas and newlines, semicolons, BOM, an Excel export, a Google Sheets paste, JSONL, malformed rows, each with its expected result.
Done when: every item has a key entry and a type tag; a test checks the key covers every item and criterion; each planted injection has a twin without the injection.
Out of bounds: running any model.
For the next ticket: file paths and the key's format.
Status / Comments: **Done 2026-11-10.** `eval/testset/`: `policy.md` (fictional Fernhollow Home Goods), `criteria.json` (4 good, 4 vague), `specs.json` (56 scenarios), `generated.json` (raw model output, `gpt-6.1-terra`, $0.14 of the $1 cap; a 4-item sample was checked before the rest), `items.json` and `answer-key.json` (60 items, built by `eval/build-testset.mjs`). Every item read by hand against the policy: 55 matched their brief; e07 was hand-edited so it fails only its named criterion (recorded in the key). Mix: 20 clean (6 correct escalations, French, Spanish, one long), 9 failures per criterion, 4 injections on failing twins. Loading fixtures and their expected results in `test/fixtures/loading/` (written byte-exact by `make.mjs`; `.gitattributes` stops git converting them). `test/testset.test.js` checks the key (6 tests) and was shown failing on a planted wrong label.
